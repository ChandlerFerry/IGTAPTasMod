# Offline engine host (enginesim)

Runs the game's own code outside Unity, so route searches run on every CPU core instead of inside the game.
The game (turbo) stays the judge: every offline best is replayed there before it becomes a route.

## How it works

| Piece | Role |
|---|---|
| `Prep/` | Rewrites the installed game's `Assembly-CSharp.dll` (Mono.Cecil) so its Unity/third-party references point at `IGTAP.UnityShim`, empties presentation-only methods (`cuts.txt`), and injects the plugin's Harmony hooks as plain calls (`hooks.txt`). `surface` lists every engine member reachable from `entries.txt` (what the shim must implement). |
| `Shim/` | `IGTAP.UnityShim`: the Unity API the game touches. Math types (`Vector2`, `Vector3`, `Mathf`, `Color`, ...) are Unity's own managed code (generated by `tools/sanitize-unity.py`), so float results match bit for bit. `Transform`, `GameObject`, components, `Invoke`, `Physics2D` forward to host backends. |
| `Box2D/` | C# port of Box2D v2 (Unity's classic 2D physics), float math in C++ order, Unity's tunables, exact world `SaveState`/`LoadState` for branching. |
| `Runtime/` | Loads a world export into real game objects (`World`), runs Unity's physics semantics on Box2D (`PhysicsWorld`: fixtures from `Collider2D.GetShapes`, layer/contact masks, raycasts incl. start-in-collider and negative distances, collision/trigger callbacks), steps ticks exactly like `TurboRunner` (`Simulation`), and drives input through the shared `MacroEngine.cs`. `OfflineSolver` is `Solver.cs` on worker threads. |
| `Cli/` | `IGTAP.EngineSim.exe replay | bench | solve`. |

Ground truth comes from the plugin (`EngineSimBridge.cs`):

- `POST /api/enginesim/trace {course, capabilities, routeId | ticks, name, world: true, freshStart}` — a turbo run from the
  solver's start state; writes `<name>.json` (start state + full state after every tick) and `<name>.world.json`
  (every GameObject, collider physics shapes, bodies, script fields, statics, Physics2D settings) to
  `BepInEx/config/IGTAPTasMod/enginesim/`.
- `POST /api/enginesim/submit {course, capabilities, ticks}` — turbo replay of an offline candidate; saved as the
  category's route (`<course>_<CAPS> <time>`) when it finishes faster than the current best.
- `POST /api/enginesim/raycast {rays: [[ox, oy, dx, dy, distance, mask]...]}` — Unity raycast probes.

`tools/enginesim-capture.py routes|random|start` captures traces; `tools/enginesim-redeploy.py` rebuilds and reloads the
plugin.

## Use

```powershell
dotnet build enginesim\Cli\IGTAP.EngineSim.csproj -c Release
$exe = "enginesim\Cli\bin\Release\net10.0\IGTAP.EngineSim.exe"
$traces = "C:\Users\deafwave\Downloads\IGTAP_Real\BepInEx\config\IGTAPTasMod\enginesim"
& $exe replay $traces\rand-*.json $traces\route-*.json   # fidelity: first tick where offline != turbo
& $exe bench  $traces\route-c1-none-4.14.json            # single-core speed
& $exe solve  $traces\route-c1-none-4.14.json --threads 16 --minutes 60 --stall-minutes 5
& $exe path   $traces\route-c1-none-4.14.json route.json  # where the course timer starts/stops along a route
```

`solve` loads the trace's world and start state on every thread, seeds with the trace's inputs (plus `--seed` traces),
writes each new best to `<traces>\offline-best\`, and sends it to the running game's `/api/enginesim/submit`
(skip with `--no-submit`; submit later by posting the saved file).

## Rules

- Nothing here changes how the game or the plugin behave; the plugin only gained read-only export endpoints and
  `submit`, which judges with the same turbo path as the in-game solver.
- A method goes into `cuts.txt` only if it is presentation or real-time-only work that turbo never sees within a run.
- Invokes: every script's `Invoke` fires on ticks (turbo only reschedules Movement's; others wait for real time).
- Fidelity is measured, not assumed: `replay` must report every tick identical on the trace corpus.

## Fidelity facts (all verified against traces)

- Game float math is Mono double precision: intermediates in double, rounded on store (`-0.3f*46f*10f/4.5f` =
  -30.666668). `Prep/MonoFloat.cs` widens float loads in Assembly-CSharp and in the shim's math types.
- Colliders: exact shapes from `Collider2D.GetShapes`; static colliders are world-space fixtures on one ground body;
  polygon radius = `defaultContactOffset` 0.01, linearSlop 0.005; Unity `maxTranslationSpeed` 100 = b2_maxTranslation
  per step; contact masks = `(layerMatrix[layer] | include) & ~exclude`, both sides must accept.
- Callbacks: collisions from Box2D touching flags (start of step); triggers from an overlap test after the step; Enter on
  the first step, Stay after; the start state primes existing contacts as already touching.
- Raycasts: direction normalized, negative distance flips the ray, start-inside hits at fraction 0 with normal −dir,
  triggers are hit (`queriesHitTriggers`).
- Every trace result matches turbo; a few runs have a late one-tick residue (Box2D GJK/TOI still follow the 2.3-era
  port, see `Box2D/NOTES.md`).

## Memory

A snapshot (for branching) is ~38 KB: the broadphase tree stores only nodes that differ from a shared base, the
pair/move buffers only their live prefix, and unchanged fixture records are shared between snapshots. `solve` prints
heap and working set every 10 s, and the host runs with `System.GC.HeapHardLimitPercent=40`, so a leak throws
OutOfMemory instead of paging the machine.
