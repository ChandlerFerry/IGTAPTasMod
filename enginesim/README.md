# Offline engine host (enginesim)

Runs the game's own code outside Unity, so route searches run on every CPU core instead of inside the game.
The game (turbo) stays the judge: every offline best is replayed there before it becomes a route.

## How it works

| Piece | Role |
|---|---|
| `Prep/` | Rewrites the installed game's `Assembly-CSharp.dll` (Mono.Cecil) so its Unity/third-party references point at `IGTAP.UnityShim`, empties presentation-only methods (`cuts.txt`), and injects the plugin's Harmony hooks as plain calls (`hooks.txt`). `surface` lists every engine member reachable from `entries.txt` (what the shim must implement). |
| `Shim/` | `IGTAP.UnityShim`: the Unity API the game touches. Math types (`Vector2`, `Vector3`, `Mathf`, `Color`, ...) are Unity's own managed code (generated by `tools/sanitize-unity.py`), so float results match bit for bit. `Transform`, `GameObject`, components, `Invoke`, `Physics2D` forward to host backends. |
| `Box2D/` | C# port of Box2D v2 (Unity's classic 2D physics), float math in C++ order, Unity's tunables, exact world `SaveState`/`LoadState` for branching. |
| `Runtime/` | Loads a world export into real game objects (`World`), runs Unity's physics semantics on Box2D (`PhysicsWorld`: fixtures from `Collider2D.GetShapes`, layer/contact masks, raycasts incl. start-in-collider and negative distances, collision/trigger callbacks), steps ticks exactly like `TurboRunner` (`Simulation`), and drives input through the shared `MacroEngine.cs`. `OfflineSolver` is `Solver.cs` on worker threads. |
| `Cli/` | `IGTAP.EngineSim.exe replay | bench | solve | humanize`. |

Ground truth comes from the plugin (`EngineSimBridge.cs`):

- `POST /api/enginesim/trace {course, capabilities; routeId | ticks, name, world: true, freshStart}` — a
  turbo run from the solver's start state; writes `<name>.json` (start state + full state after every tick) and
  `<name>.world.json` (every GameObject, collider physics shapes, bodies, script fields, statics, Physics2D settings) to
  `BepInEx/config/IGTAPTasMod/enginesim/`. The header says what a run is scored on (`Simulation.SetTarget`): `course`,
  a bonus's reward box `finish`, and for a transition `transition: true` (timed in physics ticks, `MacroEngine.PhysicsTicks`)
  with an end box `finish` or `finishStart` (the course whose start gate ends it).
- `POST /api/enginesim/submit {course, capabilities; ticks}` — turbo replay of an offline candidate; saved as the
  category's record route (`<course>_<CAPS> <time>`) when it finishes faster than the current best, or as fast in fewer
  physics ticks from the run start (`runTicks`; the saved route is replayed for its own). On a course it is also saved as
  the farm route (`<course>_<CAPS> farm <runTicks × 0.02>`) when it takes fewer `runTicks` than the farm route
  (`farmSaved`). The reply has both times.
- `POST /api/enginesim/raycast {rays: [[ox, oy, dx, dy, distance, mask]...]}` — Unity raycast probes.
- Full-TAS (`docs/fulltas.md`): `POST /api/enginesim/trace {fulltas: <run>}` writes `fulltas-<run>.json` from the fresh
  new game with the run's goals in the header (`fulltas.goals`); `IGTAP.EngineSim fulltas <trace>` searches the whole run
  in windows of goals and sends complete, faster runs to `POST /api/fulltas/submit`.

`tools/enginesim-capture.py routes|random|start|route` captures traces; `tools/enginesim-redeploy.py` rebuilds and
reloads the plugin.

## Use

All searching happens here, never in the game (`AGENTS.md` rule 7). The game is needed once per course/category to
capture a start trace and world, and afterwards only to judge new bests.

```powershell
dotnet build enginesim\Cli\IGTAP.EngineSim.csproj -c Release
$exe = "enginesim\Cli\bin\Release\net10.0\IGTAP.EngineSim.exe"
$traces = "C:\Program Files (x86)\Steam\steamapps\common\IGTAP an Incremental Game That's Also a Platformer\BepInEx\config\IGTAPTasMod\enginesim"
& $exe replay $traces\rand-*.json $traces\route-*.json   # fidelity: first tick where offline != turbo
& $exe bench  $traces\route-c1-none-4.14.json            # single-core speed
& $exe solve  $traces\route-c1-none-4.14.json --threads 16 --minutes 60 --stall-minutes 5
& $exe path   $traces\route-c1-none-4.14.json route.json  # where the course timer starts/stops along a route
& $exe humanize $traces\start-c1-none.json $traces\offline-best\1_none-1.66.json  # same-time, easier version + slack report
```

`solve` loads the trace's world and start state on every thread, seeds with the trace's inputs (plus `--seed` traces),
writes each new best to `<traces>\offline-best\`, and sends each best that beats its seeds to the running game's
`/api/enginesim/submit` (skip with `--no-submit`). Each worker walks its best's plateau: a mutation that finishes
exactly as fast (or rejoins the best's state) replaces it (`drifts` in the progress line), since a faster route is often
several mutations away, each alone no faster. A best is the fastest course time; at the same time, the fewest
physics ticks from the run start (`runTicks`), which shortens a flying start's setup before its last start-gate
crossing (off the timer, but a player still sits through it). The search never finishes a run slower on the course
timer than its best, so it doesn't search for farm routes: those come from the judged candidates. With the game closed
the best stays on disk; the plugin judges every waiting `offline-best\` file that beats or ties the saved route (its
category, then the course's other categories), and the group's file with the fewest `runTicks` when that beats the farm
route, as soon as the game is in the world and idle (a studio Optimize run holds the queue only while it starts
each target, and its running target's own files until that `solve` ends), and moves them to `offline-best\judged\`.

Splicing joins explored segments onto the best (`splices` in the progress line). The best's replay records the course
time and input tick of its first arrival in each map cell. An explore run that reaches one of those cells at least a
tick sooner runs on with the best's inputs from that cell (`Splice`). The jump button's press and release flags are
fixed where the two join. Each new best also tries up to 64 archive cells that are already ahead of it, biggest gain
first, including cells from earlier solves. On Course 4 WJ_DS_DJ this took the best from 16.58 to 15.04 within a
minute: the explore archive held faster segments that the whole-route mutations couldn't reach.

A map cell is a 48×48 square (plus the forced-path boxes passed, or a Full-TAS run's goal progress). Ground-tagged
surfaces refill wall jumps, double jumps and air dashes on every touch; `Moss`-tagged ones refill nothing
(`Movement.touchedMossyGround`; the Overworld's `moss` tilemap and the upgrade trees' `Tree*Ground`). While the last
surface touched is moss, the counts left are part of the cell, so an earlier arrival with fewer left doesn't replace,
cut or splice over a later one that has them (`OfflineSolver.CellKey`).

A solve picks up where the last solve of the same target stopped. Its search state goes to `<traces>\archive\<label>.json`
(`<course>_<caps>`) every minute and when it ends, so a solve the studio stops (it kills the process) loses at most the
last minute. The file holds every explore cell's input prefix with how
often it was picked, plus the plateau (each worker's route as fast as the best, drifted away from the saved one), and
a running count of all runs. The next solve replays the prefixes, split across its workers, to rebuild the cells
(~700k ticks for Course 4 after one session, a few seconds). Well-explored cells keep their picks, so exploration
goes on from the frontier and doesn't start again from the course start. Each worker also starts drifting from a
plateau route instead of the saved route. A plateau route's result is not submitted: its file was written when it
was found. `--fresh` ignores the file for this solve but still overwrites it.

A forced path limits which runs count. `--via x0,y0,x1,y1` boxes (the trace's world coordinates) must hold the
player's center, in order, before a finish counts; a run that enters an `--avoid x0,y0,x1,y1` box is cut. Both are
checked on every physics tick, dash ticks included. The boxes passed so far are part of every explore cell, and before
the first finish, cells past more boxes weigh more. Explore bursts get 25 extra ticks of the same stick and hold, so a
run that clears a box while coasting is saved. The search state goes to `archive\<label>-path-<--path-name>.json`,
and bests are the category's as usual. `Cli\forced-paths.json` holds standing rules that apply to every solve of their
course and categories (the studio's too), with boxes relative to the course's start gate, or to course `gate`'s start
gate when the rule names one (a transition has no gate of its own). Right now it cuts, in every
category, everything left of Course 1's wall hanging right of the buy machines and two boxes on its right (1494 to 2811
right of the gate from 275 to 531 above it, and 1160 to 1494 right from 465 below to 149 above), left of Course 2's pillar hanging right
of its buy machines, right of its two rooms' right walls (the corridor joining them), the two rooms themselves and the drop under its start floor, and left of Course 4's rightmost buy machine; Course 3's right hole in WJ_DS and WJ_DS_DJ, which
leaves the top-hole shortcut, plus a wall at the left side of the rightmost buy machine (CashPerLoop) so runs don't
wander left through the machine room and the pocket over Checkpoint (1) right of the climb; everything above Course 5's
building roof (the route goes inside); and in Course 5 WJ_DS_DJ (no orange blocks yet) the far left, the low left
corner, everything below the start floor, and the
climb up through the start room's ceiling hole: that hole is the finish, entered from above, and a run climbing up it
never started the timer. For 5to4 (from Course 5's gate) it cuts Course 5's ceiling hole and everything left of its
start gate, Courses 1 and 2 right of the pillar over each start gate (runs pass their end gates without entering), and,
above Course 3's approach shaft, everything left of the shaft's left wall.

A rule's `optional` list holds named blocks (`name`, `note`, `avoid`, `via`, same frame) that apply only when picked:
`--optional <name>` on `solve` or `map`, or the Optimize panel's "Optional avoid blocks" checkboxes. Each set of picked
blocks has its own search state, `archive\<label>-opt-<name>+<name>.json`; the map draws an optional block dashed while
it's off. Course 1 has `start-marker` (436 to 522 right of the gate, 213 to 32 below it), in every category.

```powershell
& $exe solve $traces\start-c3-wjds.json --via 10180,7100,10330,7600 --via 9900,7890,10040,7990 --path-name tophole
```

`map` replays each archive prefix to shade the cells it explored, and caches what it got per prefix (by a hash of its
inputs) in `archive\<archive name>.mapcells.bin`, so a redraw replays only prefixes that are new since the last map. It
also skips the whole redraw when nothing it reads has changed since the last map (the `--out` file's `.key` records
them). Either cache resets when the start trace, its world or the engine build changes.

A new course (bonus1, Course 4): with the game running (`python tools/enginesim-redeploy.py`), capture once, then close
the game and solve offline.

```powershell
python tools\enginesim-capture.py start bonus1 wj                     # -> start-cbonus1-wj.json + .world.json
python tools\enginesim-capture.py route bonus1_WJ bonus1 wj           # -> seed-cbonus1-wj-bonus1-WJ.json
python tools\enginesim-capture.py route 4_almost_completed 4 wjdsdj # partial route as a seed
& $exe replay $traces\seed-cbonus1-*.json $traces\seed-c4-*.json     # fidelity on the new course first
& $exe solve $traces\start-cbonus1-wj.json --seed $traces\seed-cbonus1-wj-bonus1-WJ.json --no-submit --minutes 60
```

The best file in `offline-best\` reaches the studio by itself (see above); before calling it real, do the checks in
`AGENTS.md` (trace it with `path`, say what the trick is).

A studio recording is a usable seed: the plugin keeps the player body's interpolation permanently off, so its
inputs replay in turbo tick for tick, and every sample carries the FloatingOrigin (`originX/Y`) so its position maps to
`courses.json`'s frame. A seed may carry quick restarts (`"reset": true` on a tick, the game's `respawn(true)`); they
survive `solve`'s seeds, best files and archive. Crossing a course's start gate makes the next quick restart land on
that course's reset point, so a long transition can be seeded as "reach the gate, restart, replay the course's own
transition" (5to4: the 5 → 3 explore prefix, a restart, then the 3to4 best). `path` prints why a run that didn't
finish ended.

## Humanize

A best comes out of the search full of tick-exact and analog-exact inputs, most of which don't matter.
`humanize <start-trace> <best.json>` writes `<best>-human.json`, a same-time version that is easier to play, and
`<best>-human.md`, which says how much slack each of its inputs has. `solve` does this for every new best on one
background thread (a newer best replaces one still waiting; the last one is finished before `solve` exits).

Simplify: greedy passes, repeated until none changes anything. A change stays only if the run still finishes offline in
the same time (the course timer, or physics ticks for a bonus or transition), in no more physics ticks from the run
start, and on the forced path (`--via`/`--avoid` plus `Cli\forced-paths.json`, as in `solve`).

- A partial `x` goes to full tilt, else to rest.
- A partial that has to stay goes to the middle of the band of partials (0.3..0.8 in steps of 0.05) that work.
- A stick run takes its neighbour's value, which removes a stick change. A vertical goes back to rest first, and leaves
  rest only to fill a gap in one hold.
- Presses and dashes that change nothing are dropped. Dropping a press after the button was up drops its hold and
  the release that ended it.
- Presses and dashes move as early as they still work (the buffer).

Report: every input of the human version (stick change, jump press, release, dash) is moved up to 6 input ticks
either way, one tick at a time, until it stops working. A stick run also tries the other stick values: `x` full
either way, rest, and every partial on its side; `y` −1, 0, 1. Each input is `exact` (one tick only, or one partial
value only), `free` (no limit found either way, any value), or `window N`. The report counts exact inputs in the
best and in the human version, and lists what changed. Ticks are input ticks (dash and spring ticks take none).

The human version is never a record and never replaces the best: it goes to its own file, a change that made it slower
in time or physics ticks is never kept, and the plugin never judges a `-human.json` file. The studio plays the newest one
for the category with "Play human version" (`/api/enginesim/play {human: true}`), and "Walk route" plays the newest
one as fast as the selected route (same game time for a category route, same physics ticks for a farm route) in its
place; while it plays, the studio's top bar turns violet with a HUMANIZED badge (`/api/state` `humanPlayback`).

## Rules

- Nothing here changes how the game or the plugin behave; the plugin only gained read-only export endpoints and
  `submit`, which judges with the same turbo path as the in-game solver.
- A method goes into `cuts.txt` only if it is presentation or real-time-only work that turbo never sees within a run.
- Invokes: every script's `Invoke` fires on ticks, in turbo and here.
- Fidelity is measured, not assumed: `replay` must report every tick identical on the trace corpus.

## Fidelity facts (all verified against traces)

- Game float math is Mono double precision: intermediates in double, rounded on store (`-0.3f*46f*10f/4.5f` =
  -30.666668). `Prep/MonoFloat.cs` widens float loads in Assembly-CSharp and in the shim's math types.
- Colliders: exact shapes from `Collider2D.GetShapes`; static colliders are world-space fixtures on one ground body;
  polygon radius = `defaultContactOffset` 0.01, linearSlop 0.005; Unity `maxTranslationSpeed` 100 = b2_maxTranslation
  per step; contact masks = `(layerMatrix[layer] | include) & ~exclude`, both sides must accept.
- Callbacks: collisions from Box2D touching flags (start of step); triggers from an overlap test after the step, and a
  trigger the pair wasn't touching also enters when its sensor contact touched at the start of the step (a wall jump's
  push into a wall that the step undoes still enters the checkpoint behind it); Enter on the first step, Stay after; the
  start state primes existing contacts as already touching.
- Contact order (Box2D 2.3.x, Unity's lineage, not the 2.4.1 port's): new broadphase pairs are sorted by proxy id
  before their contacts are created; the world contact list is oldest first (Collide order, and the first of equally
  early TOI hits wins); a body's contact list is newest first (the island solver's order). A collider pair's contacts
  (`Collision2D`, `GetContact(0).normal` decides a head bump) are a list: a contact that starts touching goes to the
  end, one that stops is replaced by the last. All of it decides a player wedged in a corner of one composite
  collider to the last bit (`diverge-c5-13.14` ticks 881-896: offline finished 13.14, turbo died).
- Turbo restores (`TurboRunner.Restore`) match that priming: one muted physics step at the restored pose rebuilds
  Unity's contacts, so the first tick reports Stay, not a stale Exit plus a fresh Enter. Without it a start touching a
  collider (a start under an upgrade box) ran differently in turbo from run to run.
- Turbo spawns no floating numbers (`FloatingNumberScript.ActuallySpawnText` off for the run). Their pool of 200 is only
  refilled by their own `FixedUpdate`, which turbo doesn't step. A long replay drained it; the next pop threw out of
  `courseScript.stopTracking` (no finish) or `clonesScript.DestroyClone` (the clone stays and pays again), at a point
  that depended on how much real time refilled the pool since the last run.
- Raycasts: direction normalized, negative distance flips the ray, start-inside hits at fraction 0 with normal −dir,
  triggers are hit (`queriesHitTriggers`), and the nearest hit wins across a composite's shapes too (the port's
  unclipped tree walk returned the last shape in tree order: a dash step-up onto a ledge landed 2.3 units low).
- Transforms: the player's parent (`PlayerObject`) follows the game's `FloatingOrigin` and sits at (−20200, −10539)
  on Course 4. Unity keeps only the local position, so a world position reads back as parent + (world − parent),
  rounded (20202.4453 → 20202.4434), while the body keeps the unrounded value. A scale change (facing flip) rebuilds
  the shapes but does not move the body; a position/rotation write does.
- Presses: the game takes them only in `Movement.Update`, never inside a `FixedUpdate`, so a route's presses go in at
  the tick start (`MacroEngine.BeforeTick`: the plugin's `FixedUpdate` prefix, offline before `FixedUpdate`, both after
  the pending Invokes), not at the input hook, where the game already read the buttons (Movement.cs:1033-1056). A dash
  that hits a wall takes its input tick in that tick after all; its presses go in at the wall branch's first call
  (`MacroEngine.WallTouch`: a `touchedSolidGround`/`touchedMossyGround` prefix). Traces captured before this pressed at
  the hook and differ wherever a dash met a wall with a jump pressed that tick.
- The stick: `Movement.FixedUpdate` reads the controller (`NormaliseInput(moveAction.ReadValue<Vector2>())`,
  Movement.cs:872) before the input hook, and fast fall (stick down: gravity ×1.4 while the body rises slower than 300,
  and a 1.4× fall speed cap, Movement.cs:1104-1128) and wall-slide speed (down ×1.5, up ×0.35,
  `ApplyWallslideFriction`) use that read, not the hook's `MoveAxis`. A run's stick reaches it through
  `MacroEngine.TickStick` (the plugin: a `NormaliseInput` prefix; offline: the shim's `InputAction.ReadValue`): the
  vertical of the input tick due next with x at rest, or on a tick in a dash or spring lock (no hook) the stick the last
  input tick held for the lock (`lockMoveX/lockMoveY`; unset: x at rest, y of the next input tick). That x is a super
  jump's direction (`CheckForSuperJump`).
- Spring cancel: a sideways spring locks the player (`cutsceneModes.spring`) for its `movementLock`, and those ticks skip
  the input hook, so they take no input tick. A player can still press dash on any of them, and the spring branch cancels
  the lock on a buffered dash (Movement.cs:1214-1221). An input tick's `springDash` N (`MacroStep.springDashFrame`)
  presses dash at the start of the Nth spring tick after it (`MacroEngine.BeforeTick`).
- Triggers after a facing flip: a trigger touched only at the start of the step enters, except when the touch comes from
  shapes the step's transform sync rebuilt for a new scale. A flip that rebuilt the player's box into a spring's trigger
  entered in turbo one tick later, when the step's positions overlapped (`div-c4-ff` tick 322, with fast fall).
- Every trace result matches turbo, and every tick of both `diverge-c5-*` traces. bonus1 (`seed-cbonus1-wj-*`) differs
  at one tick only: body velocity y 1.2e-14 instead of 0 from a contact on a ground seam whose normal is
  (0, 0.99999994); every later tick is identical.
- Upgrade boxes: `hooks.txt` replaces `upgradeBox.OnTriggerStay2D` with `Runtime/Shop.cs` (the buy rule, Cash, cost,
  cap, movement unlocks, Full-TAS buy goals; clone income from the native economy, `Runtime/Economy.cs`). Traces of
  Course 1's reward and clone purchases (one waiting on clone income) match turbo's result and Cash on every tick.
  In a category run (not Full-TAS) a purchase that changes the category's unlocks (the Wall jump box without WJ, any
  dash or double-jump box) ends the run (`Category unlocks changed`): the game's gate rejects such a route (README rule 11),
  and whether turbo can buy the box depends on the live save (1to2 NONE bought Course 1's Wall jump box offline and
  wall-jumped; the live save had it bought already, so turbo died).
- Buy-max boxes (`IE_BuyMax`, the statue's boosted Courses 1 and 2): turbo resumes the coroutine at every tick's end
  (`TurboRunner.EndOfFrame`), `Shop.EndOfFrame` does the same offline. A 40-buy touch of Course 1's `CashPerLoop` matched
  turbo's Cash on every tick.
- UnityEngine.Random is Unity's xorshift128 over `Random.State`'s four words (`Shim/Engine/Misc.cs`): `InitState(seed)`
  fills s0 = seed, s(i) = 1812433253 * s(i-1) + 1 mod 2^32; each draw is `t = s0 ^ (s0 << 11)` then
  `[s1, s2, s3, s3 ^ (s3 >> 19) ^ t ^ (t >> 8)]` (the new s3 is the draw); `value` = (draw & 0x7FFFFF) / 8388607;
  `Range(int, int)` = min + draw % (max - min) over the 64-bit span (equal bounds return before the draw);
  `Range(float, float)` = min * value + max * (1 - value). Verified on Unity's own published draws (macklinb/MoatShrimp's
  parity tables: 50 draws word for word) and on the game's traces, where every tick carries the state (`"random"`).
  The state is per simulation: `SimSnapshot` captures, restores and fingerprints it, and a trace's start loads it.
- Real-time play draws Random every rendered frame (LightFlicker, anim speed, ...), so real-time playback rolls differ
  from a turbo run's. Traces and the judge are turbo; real time is never compared.
- Random consumer audit (every draw a turbo tick can make, and where it is kept offline):
  - `clonesScript.SpawnClone` (clonesScript.cs:172,182): one `Random.Range(0, 101)` per speed and size roll loop, at
    least one draw each per spawn, chance or not — modeled in `Runtime/Economy.cs` (the rolls pick the clone's
    Fastness/Bigness and the next spawn's due time).
  - `clonesScript.checkIfColourClone` (clonesScript.cs:379,389): drawn only when a colour counter passes 100; such a
    run ends (`Unmodeled economy: colour clone`), so the draws are never needed.
  - `Movement.playSFX` (Movement.cs:1866-1909): a clip (or wall-slide time) draw and a pitch draw, plus the two draws
    of the `Audio.PlayAudio` its land/grassLand cases make. `cuts.txt` empties it; `hooks.txt`'s `OnPlaySfx` keeps the
    draws (`Movement::PlayFootstep` and `Movement::PlayWallSlideSfx` run un-cut: their bodies only dispatch here).
  - `Audio.PlayAudio` (Audio.cs:52,58): a clip draw and a pitch draw when the caller passed a pitch variance. Cut;
    `hooks.txt`'s `OnPlayAudio` keeps the draws (callers in a run: springs (SpringScript.cs:37), jiggle drops
    (JiggleDropScript.cs:105), footsteps/landings (Movement.cs:2475-2485), the moss tired sound (Movement.cs:2392,2401),
    the wall jump's grass step (Movement.cs:1735), tree growth (TreeController.cs:91), a box touch (upgradeBox.cs:313)).
  - `upgradeBox.buyUpgrade` and its trigger (upgradeBox.cs:624,313): the buy's particle Emit (non-buy-max), the growth
    sound of the tree a bought segment grows (upgradeTree.growSegments, once per 0.3 s audio cooldown) and BoxHit's
    clip and pitch. `hooks.txt` replaces the trigger with `Runtime/Shop.cs`, which keeps the draws.
  - Before the start snapshot, so already in its state, never in a run: `courseScript.Start`'s UpdateReward phase
    (courseScript.cs:268), `upgradeBox.OnEnable` (upgradeBox.cs:288,292), LightFlicker.cs:26,
    playerLightFlickerVariant.cs:26, RandomAnimSpeedComponent.cs:16-20, JiggleDropScript.cs:41, ObjectBobber.cs:33
    (the pooled clone prefab is Transform + SpriteRenderer + ParticleSystem only: activating one draws nothing).
  - Never stepped in a turbo tick: FloatingNumberScript.cs:89-99 (`ActuallySpawnText` is off), PlatformMover.cs:154,165.
  - Not reproduced: the draws of a block swap's re-activated boxes' `OnEnable` (upgradeBox.cs:288,292) and of the tree
    part it grows. A block swap ends the run (`Unmodeled purchase: block swap`), so the stream is never read past it;
    the tree's own growth sound draws are kept (Shop.GrowTree) but its collider changes are not modeled.

## Memory

A snapshot (for branching) is ~38 KB: the broadphase tree stores only nodes that differ from a shared base, the
pair/move buffers only their live prefix, and unchanged fixture records are shared between snapshots. `solve` prints
heap and working set every 10 s, and the host runs with `System.GC.HeapHardLimitPercent=40`, so a leak throws
OutOfMemory instead of paging the machine.

A best's replay (on every new best, adopted best and plateau drift) keeps a snapshot every 16 input ticks, not every
tick (`OfflineSolver.StateEvery`); a mutation resumes from the one at or before its first changed tick. Snapshotting
every tick of Course 4's ~670-tick route on each drift left the workers waiting on the GC most of the time (C4 WJ_DS_DJ,
30 threads: ~1,000 runs/s before, ~7,000-8,000 after).
